# cliproxy-costs API (schema 1)

All endpoints are `GET` and return `Content-Type: application/json; charset=utf-8`
with `Cache-Control: no-store`. Example responses live in
[`docs/examples/`](examples/) and are generated by the handler golden tests, so
they are exactly what the plugin returns.

## Route families

| Family | Prefix | Auth |
|---|---|---|
| admin | `/v0/management/cliproxy-costs/v1/` | CPA management key (`Authorization: Bearer <key>` or `X-Management-Key`); enforced by CPA, subject to `allow-remote` |
| read | `/v0/resource/plugins/cliproxy-costs/api/v1/` | `Authorization: Bearer <read token>`; enforced by the plugin |
| static | `/v0/resource/plugins/cliproxy-costs/dashboard`, `…/dashboard/app.js`, `…/dashboard/app.css`, `…/dashboard/chart.js` | none; contains no data |

Endpoints under each data prefix: `summary`, `quota`, `requests`, `rates`, `fx`.
Admin and read return identical JSON except that admin responses add `auth_id`
(the raw CPA auth id, which may contain file names or e-mail addresses) to
quota credentials and request attempts.

The read token is taken from the environment variable named by
`read-api.token-env` (default `CLIPROXY_COSTS_READ_TOKEN`) when the plugin is
configured. Tokens shorter than 32 bytes are treated as unset. The comparison
is constant-time over SHA-256 digests; the header name and the `Bearer` scheme
are matched case-insensitively.

## Errors

Every error is an HTTP status plus:

```json
{"schema": 1, "error": {"code": "unauthorized", "message": "missing or invalid read token"}}
```

| Code | Status | Meaning |
|---|---|---|
| `unauthorized` | 401 | read route without a valid bearer token (adds `WWW-Authenticate: Bearer`) |
| `read_api_disabled` | 503 | no read token configured on the server |
| `bad_request` | 400 | invalid query parameter |
| `not_found` | 404 | unknown endpoint or asset |
| `internal` | 500 / 503 | query failure, or storage not running |

Admin routes without a valid management key are rejected by CPA itself (401,
CPA's own body).

## Common types

- Timestamps: RFC 3339 UTC with milliseconds (`2026-09-30T17:56:39.385Z`).
  Durations: milliseconds (`*_ms`).
- Money: USD numbers; `null` means unknown, never `0`. Rates: USD per 1M tokens.
  USD is the only stored and computed unit; `fx` provides display-only
  exchange rates.
- `pricing_status`: `ok | partial | override | unknown | unsupported`.
  `partial` means a bucket had tokens but no rate (that bucket is priced at 0).
- `credential`: CPA `AuthIndex` (16 lowercase hex).
- `client`: first 16 hex of `HMAC-SHA256(secret, caller_scope)`, or `null` when
  no fingerprint secret is configured. `caller_scope` is CPA's
  `sha256("cli-proxy-api:caller-scope:v1\0" + client key)`.
- Tokens are normalized and non-overlapping: `input` is uncached input,
  `cache_read`/`cache_write` are separate, `output` includes reasoning;
  `reasoning` is informational.

## `rates?models=a,b,c`

Resolved rate cards per client-visible model id, using the same in-memory
resolution as the response interceptors. Without `models`: every model id seen
in the ledger plus configured aliases and client-model overrides. At most 500
ids.

- `status`: `ok | override | unknown`.
- `resolved_by`: `alias | override | learned | search`.
  - `override`: `pricing.overrides` entry for the model id (or for its alias target).
  - `alias`: `pricing.aliases` entry.
  - `learned`: the catalog provider recorded by the ledger for this model id.
  - `search`: exactly one match in `pricing.catalog-search-order`.
- A missing key in `rates` or a tier means that bucket is unpriced.
- `tiers` are ascending; a tier applies to the whole request when prompt
  tokens (uncached input + cache read + cache write) are **greater than**
  `above_prompt_tokens`. Missing tier keys inherit the base rate.
- `rate_card_id` = `rc_` + first 12 hex of SHA-256 over the card's canonical
  JSON (catalog ref, source, rates, tiers). A change in rates yields a new id.

Example: [`examples/rates.json`](examples/rates.json).

## `quota`

Latest passively observed subscription quota per credential, parsed from
allowlisted upstream response headers (Codex `X-Codex-*`, Anthropic
`Anthropic-Ratelimit-Unified-*`, `Retry-After`). CPA does not poll; a
credential appears after its first request with quota headers.

- `stale` is `true` when `observed_at` is older than `stale_after_ms`
  (`quota.stale-after-minutes`); every window of a stale credential reports
  `status: "unknown"`.
- Window `status`: `ok` (< 80 %), `warning` (≥ 80 % or Anthropic
  `allowed_warning`), `exhausted` (≥ 100 %, Codex limit reached, or Anthropic
  `rejected`), `unknown` (stale).
- Window `id` = `<family>:<namespace>:<window minutes>`: Codex namespaces are
  `primary`, `secondary`, or `<limit>-primary|secondary` for additional limits;
  Anthropic namespaces are the unified window names (`5h`, `7d`).
- Labels: 300 → `5 Hour`, 1440 → `1 Day`, 10080 → `7 Day`, otherwise
  `<n> Day`, `<n> Hour` or `<n> Min`.
- Anthropic utilization is a fraction in headers; `used_percent` is the
  percentage (0.53 → 53) and `used_fraction` the fraction.
- `credits` and `plan` are present only when the upstream sent them.
- `label` comes from `credential-labels`, then `subscriptions[].label`, else
  `<provider> <first 6 of credential>`.

Example: [`examples/quota.json`](examples/quota.json).

## `requests`

Four forms. `trace_id` together with `request_id` is rejected; otherwise the
first present of `trace_id`, `request_id`, `recent`, `top` wins:

- `?trace_id=<t1>,<t2>` — up to 100 ids. A trace id is CPA's inbound request id
  (UUIDv7). The full `X-Cpa-Trace-Id` response header value
  (`<yyyymmddhhmmss>-<auth index>-<trace id>`) is also accepted. Returns every
  attempt (retries, fallbacks) of each trace.
- `?request_id=<r>` — one execution attempt (CPA `UsageRecord.RequestID`; not
  the interceptor request id).
- `?recent=<1..200>[&before=<RFC 3339>][&failed=1]` — newest attempts first, for
  pagination: `{"schema":1,"attempts":[…],"next_before":"…"|null}`; each
  attempt additionally carries `trace_id`. Pass `next_before` as `before` for
  the next page. `failed=1` returns failed attempts only (`0` or absent: all).
- `?top=<1..100>[&since=&until=]` — the most expensive priced attempts in range
  (RFC 3339; defaults to the last 30 days, at most 5 years), cost descending:
  `{"schema":1,"attempts":[…]}`, each with `trace_id`. Raw rows only, so
  nothing older than raw retention appears.

Trace `status`: `complete` (≥ 1 attempt), `pending` (not recorded yet — usage
delivery is asynchronous, retry later), `expired` (a UUIDv7 older than raw
retention with no rows). `cost_usd` sums the priced attempts; `null` when none
is priced. `tier` is the `above_prompt_tokens` of the applied tier or `null`.
Success HTTP status is not recorded (CPA does not report it); `failure_status`
is set for failed attempts.

Examples: [`examples/requests.json`](examples/requests.json),
[`examples/requests-recent.json`](examples/requests-recent.json),
[`examples/requests-top.json`](examples/requests-top.json).

## `summary?since=&until=&group=&series=&tz=`

- `since` / `until`: RFC 3339; defaults to the last 30 days ending now. At most
  5 years.
- `group`: `model | provider | credential | client | hour | day | week | month`
  (default `model`). Hour keys are local `YYYY-MM-DDTHH`, week keys the ISO
  Monday (`YYYY-MM-DD`), month keys `YYYY-MM`. Time groups are sorted
  ascending; other groups by cost descending (unknown cost last). `hour` needs
  raw rows: for a range starting before raw retention the response has
  `group: "day"` instead.
- `series` (time groups only): `model | provider | credential | client` —
  each group then carries `series: [{key, label, requests, cost_usd}]`.
- `tz`: IANA zone for hour/day/week/month bucketing (default UTC).
- `label`: configured credential/client label, or `null`.
- Percentiles (`latency_ms`, `ttft_ms`, nearest rank) are computed only when the
  whole range lies inside raw retention and at most 200 000 rows match;
  otherwise they are `null`. Ranges starting before raw retention are served
  from daily UTC rollups (kept forever); non-UTC `tz` then falls back to UTC days.
- `unpriced_models`: models with unpriced requests in range. From rollups the
  status is always `unknown`.
- `cache_savings_usd` (totals and non-time groups): API-equivalent money saved
  by caching: cache read + cache write tokens priced at the applied rate card's
  uncached input rate (of the applied tier), minus what they cost. Negative
  when cache-write premiums exceed read savings. `null` when the range starts
  before raw retention, for time groups, or when nothing in the group was
  priced.
- `failures`: failed attempts by upstream status
  (`[{"status":429,"requests":3},{"status":null,"requests":1}]`; `status: null`
  = not reported), most frequent first; `null` when the range starts before
  raw retention (rollups keep no status).
- `health`: feed status (`ok | stale | error | none`), last fetch time, ETag,
  last error, feed URL, rows dropped because the write queue was full or the
  plugin was quiescing, current queue depth, rows whose `TotalTokens`
  disagreed with the provider family's identity (`token_mismatch`), raw
  retention days, last ledger write error.
- `subscriptions`: configured monthly prices (for "value" comparisons).
- `notices`: `client_fingerprints_disabled` (no HMAC secret),
  `client_fingerprints_changed` (the secret differs from the one the database
  was created with).

Examples: [`examples/summary.json`](examples/summary.json),
[`examples/summary-day.json`](examples/summary-day.json).

## `fx`

Display-only exchange rates for the dashboard and clients, configured by the
`currency` block. Nothing else changes unit: every other endpoint, the
ledger, `X-CliProxy-Cost-USD` and `usage.cost` stay USD.

- `base`: always `USD`. `rates`: units of the currency per 1 USD, rounded to
  6 significant digits; USD is always `1`. Only configured `currencies` that
  have a rate appear; a currency without a rate is omitted (never `1`).
- `source`: `ecb | fixed | off`.
  - `ecb`: the ECB euro reference rates (published once per working day
    around 16:00 CET), converted to USD: `X = eurRate(X) / eurRate(USD)`,
    `EUR = 1 / eurRate(USD)`. `currency.fixed` values fill currencies the ECB
    does not publish.
  - `fixed`: `currency.fixed` only; `as_of` and `fetched_at` are `null`.
  - `off`: `rates` is `{"USD": 1}`.
- `status`: `ok`, `stale` (the reference date is more than
  `currency.stale-after-hours` old; weekends and holidays keep the last date
  and are normal), `error` (the last fetch failed, or nothing was fetched
  yet; the last good snapshot is still served) or `off`.
- `as_of`: ECB reference date. `fetched_at`: last successful fetch or
  revalidation. `error`: last fetch error or `null`.
- `display_currency`: the configured default. `currencies`: the configured
  list in order, always including USD.

Conversion always uses the latest rate; historical amounts are not converted
at historical rates.

Example: [`examples/fx.json`](examples/fx.json).

## Cost returned on proxied responses

For Chat Completions (`openai`), Responses (`openai-response`) and Messages
(`claude`) downstream formats:

- Header `X-CliProxy-Pricing: ok|partial|override|unknown|unsupported` on
  non-stream responses and on stream headers (decided from model resolution
  only, before any usage is seen).
- Header `X-CliProxy-Cost-USD: 0.002640` (non-stream only, 6 decimals).
- Body: `usage.cost` (number, USD) and
  `usage.cost_details = {input, cache_read, cache_write, output, rate_card_id, pricing_status}`
  on the usage object: Chat root `usage` (non-stream and the stream usage
  chunk); Responses root `usage` (non-stream) or `response.usage` in
  `response.completed` / `response.incomplete`; Messages root `usage`
  (non-stream) or `message_delta.usage` (stream, with input/cache merged from
  `message_start`).
- Unknown models get only `X-CliProxy-Pricing: unknown`; other formats get
  `X-CliProxy-Pricing: unsupported`. Malformed bodies pass through unchanged.

The body annotation is computed from the response's own usage and does not wait
for the ledger. Clients correlate responses with the ledger through CPA's
`X-Cpa-Trace-Id` header and `requests?trace_id=`.
